Thunderbird WebExtension Typings

Editor support for Thunderbird's WebExtension APIs: autocomplete, parameter hints and earlier error detection. Generated from the annotated API schemas, no TypeScript required.

Use it in VS Code

Save the file in your add-on, for example as types/mv3.d.ts, and add a jsconfig.json next to your manifest.json:

{
  "compilerOptions": {
    "target": "es2022",
    "module": "esnext",
    "moduleResolution": "bundler",
    "checkJs": false,
    "lib": ["es2022", "dom"]
  },
  "include": ["types/mv3.d.ts", "**/*.js"]
}

Then close and re-open VS Code. Typing messenger.messages. now lists the available APIs, and hovering a call shows its parameters and return type.

Use it from npm

npm install --save-dev @thunderbird/webext-types

Then reference the package in your jsconfig.json with "types": ["@thunderbird/webext-types"]. Manifest V2 add-ons use @thunderbird/webext-types/mv2. The package version follows the Thunderbird major version.

Catch mistakes early

With // @ts-check at the top of a JavaScript file (or "checkJs": true in the config), typos are reported while you type:

const page = await messenger.messages.list(folderId);
console.log(page.mesages);
// Property 'mesages' does not exist on type 'MessageList'.
// Did you mean 'messages'?

Good to know

  • Your add-on does not need to be written in TypeScript. The typings are development tooling and are not needed at runtime.
  • APIs of your own Experiments are not known to the typings. Declare them in a small extra .d.ts file.
  • Do not load these typings together with another package that declares browser or messenger.
  • With checkJs enabled, plain JavaScript can produce DOM-related errors, for example value not existing on Element. That comes from TypeScript's DOM types, not from these typings.
